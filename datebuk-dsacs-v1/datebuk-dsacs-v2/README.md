# DateBuk DSACS v2.0 — integration candidate
Three plans: Free $0, Premium USD 14.99/month, Elite USD 29.99/month. Existing pricing screenshot is baseline; new quotas in src/policy.js are proposals. -1 means unlimited or enabled; 0 denied; positive daily UTC allowance. Unknown features denied. Safety is never subscription gated.

## Install
Node 22+, PostgreSQL, npm install. Fresh database: apply sql/001.sql using psql with ON_ERROR_STOP. Existing v1 only: back up and apply sql/002_upgrade_from_v1.sql instead; resolve any Plus accounts with billing provider first. Never run both on an existing installation. Set environment from .env.example securely; npm test; npm start. Verify Stripe price IDs correspond to recurring monthly USD 1499 and 2999 before enabling checkout. Use existing DateBuk identity issuer and audience. Mount behind HTTPS and rate limiting.

## Integration
GET /subscription returns plan and feature limits; POST /checkout accepts plan; POST /portal opens billing portal; POST /webhooks/stripe requires raw signed payload. GET /staff/accounts/:id is inherited basic role-based lookup; do not expose until case-scoped staff authorization is added. No public quota consumption endpoint: call consume(pool,user,feature,requestUUID,work) from authenticated business routes; work must use supplied transaction and not perform external effects. Verify account status, match membership, blocks, consent and age eligibility before admission. Boolean features use -1. Do not use quota consumption for passive UI rendering. Video initiation, scheduling, signaling and TURN issuance require server-side entitlement and participant authorization. Guest access is not implemented; default deny non-Elite video admission pending explicit guest policy. Location requires mutual consent, coarse location by default, revocation and expiry; no coordinates in billing logs. AI features require consent and moderation; do not infer religion or use readiness scores for punitive decisions.

## Release gates
Policy tests only; no live PostgreSQL, Stripe, DateBuk repository or mobile store testing. Inherited service lacks payload-bound idempotency, case-scoped staff authorization, account suspension integration, outbox and reconciliation worker. Admin/staff dashboard pages, mobile billing, guest admission, actual feature implementations and real WebRTC integration are not included. Do not deploy as final production. Add those controls, provider price validation, least-privilege database roles, audit export, concurrency tests, webhook replay tests, downgrade/revocation tests and independent security review before release. No real credentials included.
